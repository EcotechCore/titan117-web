# External services register

Every third-party service Titan117 touches, with the facts that decide how a feature can work. Written 8 Nov 2026 after we found that the feature map had GitHub pull requests opened by a bot of ours, which isn't how coding tools work and isn't what we want (decisions §25).

**The rule** (guardrails §11b): no feature that uses a third-party service is specified or built until its row here answers the six questions below, **checked against the vendor's own documentation or terms**, with the date and a link. A blog post or a forum answer is a lead, not a source. Anything not yet checked says **To verify**, and a phase can't start while one of its rows does.

1. **Whose account?** Ours, or the user's own.
2. **Who does it act as?** What the other side (the vendor, a repo owner, a recipient) sees as the author.
3. **Where do the credentials live?** Our server's environment, or the user's OS keychain. Never in the app's code.
4. **Approvals and reviews:** app review, verification, allowlists, security assessments, and how long they take.
5. **Terms:** resale, automation, scraping, data use, anything the vendor forbids.
6. **Cost:** who pays, and whether it runs through our credits.

**Default when in doubt:** the user's own account, acting as the user, credentials in their keychain, the vendor's official API and sign-in flow. Only OpenRouter goes through our credits; every other paid service is the user's own account (decisions §31).
